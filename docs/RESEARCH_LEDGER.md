# Persistence Framework — Research Ledger

## Purpose

This is the standing project-control document for the persistence framework. It exists to prevent circular work, rediscovery of settled issues, and drift away from the canonical manuscripts and frozen validation plan.

**Rule:** Before opening a new theory branch, numerical experiment, data reconstruction, or interpretive change, check this ledger. A new route must either advance an open item below or explicitly justify reopening a closed decision.

   - Historical/orientation test after the universal stationary parameters are frozen.

## Standing scientific interpretation

- The phenomenologically non-GR-observable version of the framework is a **covariant, strictly retarded effective extension of gravitational response**, not merely an exact rewriting of Einstein gravity.
- The ordinary Einstein response remains explicit. The persistence correction must vanish continuously in the GR limit.
- The hereditary sector may carry independent state/initial data. Do not equate “no new propagating spin-2 pole” with “no additional state degrees of freedom.”
- The current paper’s dynamical state frame `n^mu` is physical. Coordinate motion alone is not persistence; matter motion relative to the state frame is the relevant invariant content.
- Rotation, lensing, and cosmology are linked tests of one universal response framework, not independent opportunities for sector-by-sector retuning.
- The Milky Way halo solutions, SPARC `Vobs`, residual acceleration, Portail/Hunter orbit weights, or any other target observable may **never** determine the source profile, history orientation, or universal persistence parameters in a confirmatory run.

## Canonical weak-field bridge

The current paper supplies the Stage 9 chain directly:

1. baryonic energy/current relative to the state frame:
   - `epsilon ~ rho_b c^2`
   - `q_i ~ rho_b c v_i^rel`
2. scalar history invariant:
   - `I_phi = tau_* (dot epsilon_M + chi_q c D_mu q^mu)`
3. source maps:
   - `J_phi = -(g_phi/M_*) I_phi`
   - `J_A_mu = -(g_A/M_*) q_mu`
4. retarded scalar/vector evolution;
5. composite inherited perturbation `H_mn(phi,A,n)`;
6. observable metric `g_obs = g + epsilon_H H`;
7. stellar acceleration/lensing from the appropriate metric components.

For the minimal stationary axisymmetric pressureless disk, the canonical extra radial force is vector-current dominated:

`a_R^(A) = zeta_A v_c B_P,z`.

The source current is built from the baryonic surface-density profile and the **self-consistent model velocity**, never the observed rotation curve inserted as a source.

## Public H I standardization rules

These are frozen before calibration:

- Canonical stored H I is hydrogen-only face-on `Sigma_HI` in `Msun pc^-2`.
- Source radii are converted to frozen SPARC distance: `R_frozen = R_source D_SPARC / D_source`; surface density is not distance-scaled.
- No inward or outward H I extrapolation.
- Linear interpolation only inside the measured radial range.
- Downstream atomic gas uses one declared factor `Sigma_atomic = 1.33 Sigma_HI`.
- Stellar reference M/L is disk 0.5, bulge 0.7.
- Public map reduction uses the previously frozen geometry where applicable: map-derived center/major-axis fallback, frozen SPARC inclination/distance, 2-beam central mask, 0.5-beam annuli, zero-valued image background excluded, median with p16/p84.
- Edge-on galaxies are not forced through the thin-annulus deprojection.
- Public accessibility and raw-file redistribution rights are tracked separately.

## Do-not-digress gate

Before pursuing a new idea, answer:

1. **Is it already contained in the canonical current paper?** If yes, use that formulation rather than reinventing it.
2. **Does it resolve an open ledger item or referee criticism?** If not, deprioritize it.
3. **Does it advance a halo-blind prediction, data freeze, or independent falsification?** If not, justify why it is necessary.
4. **Is it a derivation or a new assumption?** New assumptions must be labeled and may never be selected because they improve a target curve.

If a proposed path contradicts a CLOSED or PERMANENT-GUARDRAIL item, explicitly reopen and justify that item before doing work.
